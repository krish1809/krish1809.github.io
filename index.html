devpilot-pied.vercel.app

01AI agent2026

DevPilot

An AI software engineer that turns GitHub issues into tested pull requests, and never ships without a human’s approval.

  • A LangGraph pipeline (retrieve → plan → code → test → review → approve) checkpointed to Postgres, so runs survive crashes and restarts.
  • Repository tests run in a throwaway Docker sandbox: no network, CPU, memory and PID limits, non-root.
  • Each approval is bound to the SHA-256 of the exact diff; if anything changes, publishing refuses.
  • Hybrid code search (pgvector + full-text), its own MCP tool server, and evaluation on SWE-bench Lite with the official harness.

aura · chat

02Multimodal AI2026

Aura

An emotional-support companion that listens to how you feel, works out why, and shows its reasoning for every reply.

  • Fuses text, voice (Whisper + wav2vec2) and facial expression (ResNet-18) into a single emotion reading.
  • A two-head RoBERTa model finds the cause of a feeling; a strategy model picks one of 8 ESConv support strategies.
  • Replies come from a fine-tuned Llama 3.2 3B, with a “Why this reply?” panel and a memory graph you can inspect and erase.
  • Crisis language bypasses the LLM entirely and returns a fixed, carefully worded message with real helplines.

03Distributed systemsTeam of 4

CSD Group Chat

A real-time, Discord-style chat with encrypted storage, signed messages and a custom Go load balancer.

  • Public channels, invite-only rooms and DMs, with membership enforced by the server on every read, write and broadcast.
  • Messages are stored as AES-256-GCM ciphertext; any edit to a stored message fails decryption and is flagged.
  • Runs behind a Go load balancer with TLS, round robin, health checks and retries.

My part: ECDSA P-256 message signing and the trust-on-first-use key registry, deploying the load balancer on four lab machines with scaling and failover experiments, and the rooms, DMs, mentions, replies and reactions.

04Geospatial2026

Village Pond Planner

Helps village administrators decide where to build ponds, using terrain, catchment and rainfall analysis.

  • Fetches a real 30 m elevation model (SRTM via OpenTopography) for any block drawn on the map.
  • Hydrology pipeline: depression filling → D8 flow direction → flow accumulation → TWI/TPI siting → river exclusion → catchment delineation.
  • Ranks pond candidates by footprint, catchment and water volume, using historical rainfall.
  • FastAPI gateway, a separate OpenCV microservice and PostGIS, all containerised.

About

Curious about how things actually work.

I’m Rishi Kharya, an undergraduate at IIT Bhilai. I learn a system best by building the thing on top of it, and then the thing underneath it.

So my projects tend to come in pairs. An AI agent that writes code, and the sandbox that stops that code touching anything it shouldn’t. A group chat, and the signatures that prove who sent each message.

I try to keep my engineering honest: test it, measure it before claiming it, and say clearly what a project doesn’t do yet.

01

Assume input is hostile

DevPilot treats issue text, files and tool output as untrusted, and only runs code in a sealed sandbox. The group chat signs every message and detects tampering at rest.

02

Show the reasoning

Aura explains every reply: the emotion it read, the cause it found and the strategy it chose. DevPilot shows its plan, diff, retrieved context and every LLM call.

03

Measure, don’t guess

DevPilot is scored on SWE-bench Lite with the official harness, not by eye. The group chat was load-tested for scaling and failover on four lab machines.
